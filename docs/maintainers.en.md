# Maintainer guide

[← back to the README](../README.en.md)

For maintainers of this repository: local builds, regression checks, and publishing to
ClawHub. External contributors should start with [CONTRIBUTING.md](../CONTRIBUTING.md).

---

## Development

`shared/` is the **single source of truth**. The scripts and reference files under
`skills/<name>/` are generated copies, because `npx skills add` installs by copying
directories — each skill has to be self-contained.
**Run `npm run build` after editing anything in `shared/`.**

```bash
npm run build          # sync shared/ into all 26 skill directories
npm run build:check    # verify sync only (used by CI)
npm test               # unit tests + compliance script tests
npm run eval           # structural + executability regression (dry-run, no cost)
npm run eval:live      # golden cases from evals/<skill>/cases.json (real generation, needs a key)
npm run doctor         # which backend is usable right now
```

`npm run eval` verifies frontmatter validity, description length and trigger phrases,
body under 500 lines, that every relative link and image resolves, that golden-case
fixtures exist, and **that every command written in the docs actually runs**. Break a
prompt template or a parameter and this step goes red immediately.

### Adding a skill

1. `skills/<name>/skill.md`
2. Add its description and required shared files to `scripts/skills.config.json`
3. Add default model and parameters to `shared/scripts/lib/tasks.json`
4. Add a Chinese display name to `scripts/skill-display-names.json` (the publish script
   exits outright if it is missing)
5. `npm run build && npm test && npm run eval`

## Publishing to ClawHub

The publish script is `scripts/publish-skills.mjs`. It rewrites each
`skills/<name>/skill.md` into the `SKILL.md` ClawHub expects — renaming the file, turning
`../../docs/…` asset references into absolute GitHub URLs, adding a version — stages the
result in `.publish-tmp/` and publishes one by one. Source files are never touched.

```bash
npm install                # installs the clawhub CLI (devDependency)
npm run clawhub:login      # log in before the first publish; the token is stored locally
npm run publish:dry        # print slug / version / display name only, publish nothing
npm run publish:skills     # publish for real (skips what is already in .publish-skills.done)
```

| Command | What it does |
| --- | --- |
| `npm run publish:dry` | `--dry-run`, preview the skills and versions about to go out |
| `npm run publish:skills` | Publish, resumable: successes are recorded in `scripts/.publish-skills.done` |
| `npm run publish:force` | `--force`, ignore the resume record and republish everything |
| `npm run publish:reset` | Clear the resume record and the `.publish-tmp/` staging directory |
| `npm run clawhub:whoami` | Check the login state |

Extra arguments pass through after `--`:

```bash
npm run publish:skills -- --only flat-lay,one-shot     # publish specific skills only
npm run publish:skills -- --ref main --keep-staging    # pin the asset ref, keep staging for debugging
npm run publish:skills -- --changelog "fix size args"  # custom changelog
```

Other flags are documented in the script header: `--owner`, `--repo`, `--tags`.

Two preconditions:

- **A new skill must have a Chinese display name in `scripts/skill-display-names.json`**
  first, or the script errors out and exits;
- **Changes under `docs/` and `skills/` must be pushed first** — published asset URLs
  point at `<owner>/<repo>@<ref>`, so anything unpushed shows up as a broken image. The
  script WARNs when the working tree is dirty.

## Redrawing the README SVGs (repolish)

The banner, overview card, footer report card and every table image are ordinary files
generated by [repolish](https://github.com/asale-ai/repolish). **Do not just run
`repolish --apply` and call it done** — there are two traps:

- the description language defaults to `auto`, which paints the English tagline into the
  Chinese README's banner and overview card;
- repolish does not know about the three English images under `.repolish/en/` and will
  never refresh them.

Run it in this order and both languages come out right:

```bash
repolish --stages artifacts --apply                  # badge + every table image, both languages

# the three Chinese images — the language must be explicit
repolish --stages artifacts --apply --artifact hero     --lang zh-CN -o .repolish/hero.svg
repolish --stages artifacts --apply --artifact overview --lang zh-CN -o .repolish/overview.svg
repolish --stages artifacts --apply --artifact score    --lang zh-CN -o .repolish/card.svg

# the three English images
repolish --stages artifacts --apply --artifact hero     --lang en -o .repolish/en/hero.svg
repolish --stages artifacts --apply --artifact overview --lang en -o .repolish/en/overview.svg
repolish --stages artifacts --apply --artifact score    --lang en -o .repolish/en/card.svg
```

Table images are named after the heading slug, so **editing a subheading renames the
file** — update the `<img src>` in the README to match and delete the orphaned SVG.
